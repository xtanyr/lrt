# LRT v1: план завершения

Основание: roadmap documentation/01–12 и ROADMAP_AUDIT_2026-09-14.md. Пользователь поручил завершить проект 14 сентября 2026.

## Архитектура и ограничения

Сохраняем NestJS/Prisma/PostgreSQL и React/Vite. Расчёт рейтинга выполняется сервером. Форма хранит факты, планы и анализ; чтение истории использует снимок параметров. Права проверяются по актуальным назначениям пользователя на сервере. Существующие данные считаются ценными; допускаются только добавочные миграции, без reset и перезаписи истории. Реальные таблицы ожидаются для проверки импорта. Не публикуем приложение без определения сервера.

## Договорённости модулей

- Канонический пользователь API: `id`, `name`, `email`, `role`; назначения читаются из БД.
- Канонические параметры метрики: `thresholdStrong`, `thresholdMedium`, `pointsStrong`, `pointsMedium`, `pointsCritical`; старые frontend-алиасы временно синхронизируются для совместимости.
- Поля отчёта: текущие `revenue`, `drinksCount`, `metricValues`, `analyses`; дополнительные JSON `formData` для финансов и планов, `ratingSnapshot` для результата и порогов.
- Общий результат: `rating`, `results` (metricId/name/unit/value/zone/points), период и статус. Исторические результаты не пересчитываются при чтении.
- Работаем в предоставленной папке C:/LRT: Git-репозиторий не обнаружен, worktree/коммиты неприменимы до его появления.

## Журнал

- 15 сентября: единый серверный расчёт рейтинга и настройка метрик — 28 тестов прошли; seed идемпотентный. Форма лидера переписана: кофейня/период, факты/планы/финансовые поля/ссылки и необязательный анализ сохраняются вместе; ошибки сохранения видимы, редактирование после отправки доступно до блокировки. Два UI-теста формы прошли, TypeScript проходит. Dashboard использует актуальные назначения и ReportsService; клиентские повторные расчёты заменены чтением серверного снимка. Сквозная приёмка, агрегаты по периоду, конфигурация цветов, ИПВ и развёртывание ещё не завершены. Исторические данные не изменялись.

- 16 сентября: импортер проверен на трёх экспортированных Google Sheets: два файла с листом «Метрики» распознаны как исторические, третий корректно отклонён как неподходящий. В исходных листах у части периодов отсутствует выручка: админ вводит её в предварительном просмотре, затем импорт сохраняет исходные значения, баллы и старую схему без перезаписи существующих периодов. Добавлены Dockerfile, compose, nginx и пример окружения. `docker-compose config --quiet`, backend build, 91 unit-тест, frontend build, 13 UI-тестов и сквозной API-сценарий успешны. Docker-образы API и web собраны, Compose-стек с чистой PostgreSQL-базой поднят: миграции применены, API и nginx отвечают. В Dockerfile API очищается TypeScript-инкрементальный кеш, чтобы в образ попадали JavaScript-файлы, а не только декларации типов.

- Решение пользователя: исторические данные и рейтинги оставляем как есть. Импорт сохраняет исходные значения, баллы и старую конфигурацию 9 метрик (13/9,6) в историческом снимке; пересчёт по новым правилам запрещён. Новые отчёты используют 10 метрик по roadmap. База содержит только тестовые данные; итог работы — v1 и подготовка к развёртыванию, без запуска на сервере.

- 14 сентября: повторно проверена структура; изменений относительно аудита не обнаружено. Заданы вопросы об эталонных таблицах, сохранении данных и размещении. Начальные проверки из аудита: backend/frontend build, 41 тест — успешны; не заменяют сквозную приёмку.
